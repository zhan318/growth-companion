## 四、逐条详述

### BUG-1（P0）嵌入模型静默回退

**现象**：配置值写错（拼错、留空、填 `api`），系统照常启动、照常返回答案，但实际用的是英文模型 `all-MiniLM-L6-v2`（384 维）。

**证据**（`knowledge/embeddings.py`，`get_embedding()` 结尾）：

```python
# default → ChromaDB 内置模型
logger.info("Embedding: ChromaDB 内置 all-MiniLM-L6-v2")
return ChromaDefaultEmbeddings()
```

**根因**：`else` 分支兜底，而不是抛异常。任何非白名单值都落进来。

**影响**：`config.py` 自己的注释已写明「all-MiniLM-L6-v2 对中文 query 几乎失效，dense 命中率实测 4.8%」。也就是说这个分支一旦命中，中文检索基本报废，但**日志只有一行 info，接口不报错**，用户只会觉得「最近答得不准」。

**修法**

| 方案 | 做法 | 评价 |
|---|---|---|
| A（推荐） | 白名单校验：值不在 `{sentence-transformers, deepseek}` 内 → 启动即 `raise ValueError` | 一次改动永久生效，符合「显式失败」原则 |
| B | 保留回退但升级为 `logger.error` + 启动自检接口暴露当前模型 | 仍会错跑，只是更容易被发现 |

---

### BUG-2（P0）配置项与代码不对齐

**现象**：`.env.example` 第 44 行写：

```
# KNOWLEDGE_EMBEDDING=default          # default | sentence-transformers | api
```

而代码判断的是字符串 `"deepseek"`。

**根因**：模板与实现各自演进，没人把两者绑在一起。

**影响**：

- 填 `api` → 不匹配 → 触发 BUG-1（英文模型）
- 填 `deepseek` → 调 `deepseek-embedding` → **官方无此模型，直接 404**
- 也就是说：**除默认值外，没有第二个能用的值**，配置项形同虚设

**修法**：与 BUG-1 的 A 方案合并做——白名单同时决定「合法值列表」，并把 `.env.example` 里的选项改成真实可用值（`sentence-transformers` / `api`→若接入真实 provider 则改名 / `deepseek` 删除）。

---

### BUG-3（P0）检索无阈值，无法判定「库里没有」

**现象**：任何问题都会返回 3 条参考资料，包括完全无关的问题。

**证据**

```python
# vector_store.py get_retriever()
self._retriever = self._store.as_retriever(
    search_kwargs={"k": k or config.RETRIEVE_TOP_K},
)
```

只设 `k`，未设 `score_threshold` / 未用 `search_type="similarity_score_threshold"`。

```python
# pipeline.py:513
merged = rerank(question, candidates, top_n=top_k)   # threshold 未传
```

而 `reranker.py` 的签名是 `rerank(query, docs, top_n=3, threshold=None)`，docstring 明确写「threshold 可用于『知识库无相关内容』的判定」——**设计有，接线漏了**。

**实测佐证**：中文短句的余弦相似度普遍偏高，语义完全无关的两句话也能到 0.53。所以「看起来有分」不等于「真的相关」，必须设阈值。

**修法**

| 方案 | 做法 | 评价 |
|---|---|---|
| A（推荐） | 组合判据：`Top1 ≥ 0.65` **且** `Top1 − Top5 ≥ 0.08` 才认为命中，否则走「知识库无相关内容」 | 绝对线防明显无关，相对落差防「都很像」的假命中 |
| B | 只设绝对阈值 | 简单，但换语料/换模型就漂 |
| C | 给 reranker 传 threshold，用 Cross-Encoder 分数判定 | 最准，但多一层模型成本；建议作为 A 的补充（P1） |

**注意**：具体阈值必须用数据校准——拿 20 道有答案的题 + 10 道资料外的题，画「命中 vs 未命中」的分数分布，取分界点。不要拍脑袋。

---

### BUG-4（P1）collection 无模型指纹

**现象**：`VectorStore.__init__` 用当前配置的 `get_embedding()` 去连已有 collection，从不校验库里向量的模型与维度。

**根因**：Chroma 的 collection metadata 里没存 `model_name` / `dim` / `built_at`。

**影响**：换嵌入模型后，旧向量与新 query 向量不在同一空间，轻则检索全是垃圾，重则维度不匹配报错，且**很难定位原因**。而 bge-small（512 维）与 embedding-3（2048 维）之间换一次，就必须整库重建。

**修法**：建 collection 时写入 metadata `{"embedding_model": ..., "dim": ..., "built_at": ...}`；启动时比对，不匹配则拒绝服务并提示 `reindex`。

---

### BUG-5（P1）嵌入模型重复加载

**现象**：`get_embedding()` 没有缓存，而 `VectorStore.__init__` 每次都调用它（`vector_store.py` 第 25 行与第 93 行）。项目有 `knowledge_base` 和 `obsidian` 两个 collection → **加载两份 BGE 进内存**。

**对比**：`reranker.py` 用了 `@lru_cache(maxsize=1)`，说明这个手法在本项目里是已知的，只是嵌入这边漏了。

**修法**：给 `get_embedding()` 加 `@lru_cache(maxsize=4)`（返回的是无状态对象，可安全共享）。

---

### BUG-6（P1）DeepSeek 嵌入死分支

**证据**（`embeddings.py`）：

```python
class DeepSeekEmbeddings(Embeddings):
    def __init__(self, api_key: str, base_url: str = "https://api.deepseek.com"):
        self.model = "deepseek-embedding"      # 官方不存在
```

**影响**：配置一旦指向 `deepseek`，首次建库即 404。目前是死代码，未被走到。

**修法**：删除整个类，或替换为真实可用的 provider（智谱 `embedding-3` 等）。**先删更干净**，需要时再加。

---

### BUG-7（P2）导入方式不一致

`get_embedding()` 内部用 `from config import DEEPSEEK_API_KEY`（绝对导入），同项目其他处均为 `from .config`。不同启动路径下会 `ModuleNotFoundError`。随 BUG-6 一起删即可消失。

---

### BUG-8（P2）参数从未被验证

`.env` 中没有任何 `KNOWLEDGE_*` 变量，全部走 `config.py` 默认值（`CHUNK_SIZE=500`、`CHUNK_OVERLAP=50`、`RETRIEVE_TOP_K=3`、`RECALL_N=20`、`RERANK_ENABLED=true`）。不算 bug，但意味着这些数值从未经过对比实验。

**建议**：至少对 `CHUNK_SIZE` 做一次 500/800/1200 的召回率对比，这是毕设论文里能直接写的一节。

---

### BUG-9（P2）模板写法易误抄

```
# KNOWLEDGE_EMBEDDING=default          # default | sentence-transformers | api
```

带空格的 `|` 分隔写法若被整行复制进 `.env`，会得到非法值（进而在旧代码里触发 BUG-1）。建议改成每行一个注释示例。

## 六、对毕设项目的迁移结论

毕设（`E:\pythonprojects\python-course-agent`）代码重写，**以下三条已写入其 `specs/001-knowledge-qa/design.md`**：

1. **配置只接受白名单，非法值启动即失败**，禁止 `else` 兜底换模型。
2. **collection metadata 必须存 `embedding_model` / `dim` / `built_at`**，启动校验，不匹配明确要求重建。
3. **检索判据用「绝对阈值 + 相对落差」双条件**，且阈值必须由 `fixtures/questions.md` 的 20 题 + 10 道资料外题校准，不许拍脑袋。

额外两条经验直接复用：

- 本地 `bge-small-zh-v1.5` 是可行方案（本机 3.12.7 上已验证），**离线、零成本、512 维**，适合答辩演示。
- 中文场景**不要**用 ChromaDB 内置的 `all-MiniLM-L6-v2`（英文模型，本项目实测 dense 命中率 4.8%）。
