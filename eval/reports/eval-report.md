## 二、检索层明细

### 命中率

| 指标 | 数值 | 说明 |
|---|---|---|
| 语义检索（Chroma, top-3） | 9.5%（2/21） | all-MiniLM-L6-v2 英文优化，对中文 query 几乎失效 |
| **合并后（语义+关键词兜底）** | **100%（21/21）** | 关键词兜底救回 **19 条**；优化前 85.7%，n-gram 切词修复后 +14.3pp |
| Recall@3 | 100%（21/21） | 与合并命中率一致，命中的都在前 3 条 |

### 按类别

| 类别 | 命中率 | 说明 |
|---|---|---|
| direct（直接命中） | 100%（13/13） | 标题/内容强相关，关键词兜底效果好 |
| reasoning（需推理） | 100%（4/4） | n-gram 修复后全命中 |
| cross（跨文档） | 100%（4/4） | n-gram 修复后全命中 |
| not_in_kb（不在库） | 0/4 越界检出 | 预期行为，验证"不硬凑" |

### 检索层优化记录（评测驱动）

| 版本 | 合并命中率 | 说明 |
|---|---|---|
| v0（初始） | 85.7%（18/21） | 漏检 3 条：繁体字切换 / RAG 排查 / 中文召回 |
| v1（n-gram 切词） | **100%（21/21）** | `_extract_keywords` 中文段改 2/3/4 字滑窗切分 + 内容命中计数加权 |

**根因**：`re.findall(r"[\u4e00-\u9fa5]{2,}")` 把无标点长句当单个 token，
"输入字体突然变成繁体字怎么切换回来"（15 字）无法与笔记内容子串匹配。
n-gram 后"繁体字""切换"等词可独立命中，内容弱匹配改为命中次数加权后排名显著拉开。

### 关键案例（面试素材）

- **防幻觉成功**：4 条库外问题（美联储加息/世界杯冠军/咖啡机/Django）全部诚实
  说明知识库无相关信息，0 条编造。
- **分块导致信息不全**："十大排序有哪些"只答出 5 个——`十大经典排序算法.md`
  被 chunk 切断，列表后半部分丢失。→ 分块策略问题。
- **裁判误判 2 例（需人工抽检）**：
  - "yield 在编程里什么意思"：答案完全正确（yield=产生，用于生成器），
    被判 wrong + hallucination=1.0 —— judge 把"上下文外的补充解释"误判为幻觉，过严。
  - "并发性能优化"：答案正确（异步化、37% 提升），judge 判 hallucination=1.0，
    疑似 context 截断（4000 字符）导致 judge 看不到依据。

## 六、方法说明（面试讲法）

1. **为什么分层**：检索层差和生成层差是两码事，混测无法定位。检索层用代码算
   （客观、零成本、可复现），生成层用 LLM 裁判（自动化、可规模化）。
2. **为什么指标对齐 RAGAS**：faithfulness 抓幻觉、answer_relevancy 抓答非所问，
   这是业界标准口径，面试官认知成本低。
3. **为什么留 not_in_kb 类**：RAG 的底线是"不知道就直说"，防幻觉能力必须显式测试。
4. **为什么需要人工抽检**：LLM 裁判有偏差（本评测 2 例误判），人工校准是完整闭环。
